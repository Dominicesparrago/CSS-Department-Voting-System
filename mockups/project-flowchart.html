Project flow

Each lane shows a user/system path. The arrows read left to right on desktop and top to bottom on mobile.

Student laneRegistration to confirmation
01 StartSign in or register

Student uses official `.scc@gmail.com` email and a 7-9 digit student ID.

02 ValidateCreate voter profile

Year level and section decide the year-representative race.

03 BallotOpen scoped ballot

16 department races plus the one matching year-rep race.

04 ReviewSelect every race

All selections are reviewed together before final submission.

05 FinishSubmit once

Vote transaction writes immutable votes and marks the voter as voted.

Admin laneElection management
01 GateRole-gated login

Admin claims unlock the dashboard and election controls.

02 SetupManage candidates

Add candidate names, year, section, platform, status, and photo data.

03 OperateControl lifecycle

Draft, open, close, and publish the current election.

04 MonitorView charts

Track voters, ballots cast, turnout, and live candidate tallies.

05 ExportAudit and CSV

Export voter/results data for committee records after polls close.

02 InviteAdd admin

05 TraceAudit trail

Integrity loop

How one verified vote stays protected

This is the compact control loop behind the whole system: validate, scope, submit once, audit, then publish.

1Validate account

Official email and unique student ID create one voter profile.

2Scope ballot

Year level filters the representative race while keeping department races.

3Submit atomically

Selections are written in one transaction, not as partial votes.

4Prevent duplicates

Vote IDs and `hasVoted` state block second submissions.

5Recompute tallies

Results are derived from immutable vote documents.

6Publish auditably

Closed results and admin actions stay reviewable.
